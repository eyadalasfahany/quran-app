# 0074 — Way2Quran reciters, hosted by Taybah on Cloudflare R2

Date: 2026-11-07 · Status: **accepted** (developer decisions, 7 Nov 2026; the Sources credit ships without a frame, by developer approval) · Extends ADR 0061 (a second reciter source on the same R2 host, same copy-once pipeline, same partial-recording rule) and ADR 0060 (timings made by Taybah). Amends non-negotiable 2 in `CLAUDE.md` (the list of audio hosts: «for MP3Quran reciters» becomes «for MP3Quran and Way2Quran reciters», done 7 Nov 2026) and `docs/content-plan.md` (recitation audio table). Plan: `docs/plans/way2quran-reciter.md`.

## Context

Taybah plays the 20 QF reciters (ADR 0008) and, from ADR 0061, MP3Quran reciters copied to R2. Way2Quran (https://way2quran.com) is a second recitation site. It is not in the MP3Quran catalogue (v3 API checked by the coordinator, 7 Nov 2026). Facts read on 7 Nov 2026:

- A reciter page (`https://way2quran.com/ar/reciters/{slug}`) embeds the file URLs in its HTML. URL shape: `https://media.way2quran.com/{slug}/{riwayah-folder}/{file}.mp3`. `robots.txt` returns 200; it carries a content-signals header («ai-train=yes, search=yes, ai-input=yes», «da'wah waqf — spread»). That header is a statement about crawling, not a licence, and this ADR does not rely on it.
- Muhammad Abadh (محمد عبادة), page `muhammad-abadh`: 114 files `…/hafs-an-asim/NNN.mp3`, about 1,845 MB, variable bit rate about 140–180 kbps, 48 kHz stereo, each with an embedded PNG cover-art stream (coordinator's check; the HEAD of 001, 002 and 114 by the planner returned `content-length`, `accept-ranges: bytes` and `last-modified`, and **no `ETag`**). Surah 90 once timed out on a HEAD.
- Hossam El Din Ebadi (حسام الدين عبادي), page `hossam-el-din-ebadi`: 54 Hafs files of 114 (about 328 MB), plus Warsh files on the same page. The page lists 537 occurrences of Hafs URLs and 28 of Warsh URLs (82 distinct files in the HTML; the coordinator verified the 54 Hafs files by HEAD). File names are **not uniform**: most are zero-padded `NNN.mp3`; `79`, `80`, `82`, `83`, `84`, `87` are `79.mp3` and so on.
- The files carry ID3 tags that name `www.midad.com` («مجموعة مواقع مداد») in `album` and `comment` (read from Muhammad Abadh's `001.mp3`). Whoever owns the recording rights, the tags do not name the reciter as owner. See open item 2.
- The Cloudflare copy Worker accepts only `cdn.mp3quran.net` and keys under `audio/mp3quran/` (`tools/r2-copy-worker/src/index.ts`, lines 17–19).

## Decisions

Developer, 7 Nov 2026 (verbal, in person):

1. **Rights basis.** The developer was given permission in person for **every reciter on Way2Quran**: Taybah may (a) host the files itself, (b) allow offline download, (c) publish timings derived from them. The first two reciters are Sheikh Muhammad Abadh and Sheikh Hossam El Din Ebadi. Each of them gave the developer the same permission in person (separate entries below). No licence text exists: Way2Quran states none and the permission is not written. Streaming from Way2Quran's servers was not part of the choice, so the app never streams from them. The developer accepts the risk that the permission is verbal.
   - Grant 1: Muhammad Abadh, 7 Nov 2026, in person.
   - Grant 2: Hossam El Din Ebadi, 7 Nov 2026, in person.
   - Catalogue-wide: the developer states that the permission covers every Way2Quran reciter. A further reciter is added by data (decision 7) and gets its own line in the plan's grant table when it is added, with the date and how the developer knows.
2. **Attribution.** Settings › Sources credits (a) the reciter by name, (b) Way2Quran as where the files came from, and (c) Midad (www.midad.com, «مجموعة مواقع مداد») as the producer named in the files' tags, where the files carry that tag. As for MP3Quran (ADR 0061 decision 2), the wording is the developer's, and the lines go in the Arabic and English i18n files. Developer approval, 7 Nov 2026: the credit is added to the existing Sources screen **without a new frame** (an approved difference under ADR 0010): one Way2Quran entry built from the existing source-row component, naming each reciter and Midad as producer. The app never says how the permission was obtained or that permission exists (developer, 7 Nov 2026); the grants are recorded here only.
3. **Hafs only in v1.** Way2Quran also publishes other riwayat (Ebadi's page lists Warsh). The app's text and ayah numbering are Hafs (Tanzil), and another riwayah can divide ayahs differently (ADR 0061 decision 10). Only the `hafs-an-asim` folder is read. The source list holds no file of another riwayah, and the lister reports how many it ignored. Other riwayat are a separate decision, as for MP3Quran.
4. **Same rules as ADR 0061.** Copy once, never link (decision 4); content-hashed immutable keys (5); the public host `audio.taybah-app.com` (6); R2 keys only in the developer's env and the `taybah-app / production` GitHub environment (7 and the 5 Nov amendment); a committed manifest, no live fetch (8); rollback by marking resources inactive (13). Bytes are copied as they are: no transcode, no tag or cover-art stripping, so `size_bytes` equals the source `Content-Length` and the sha256 names the source bytes.
5. **Data model.** A second content source `way2quran` (a `content_sources` row, permission `granted`, developer decision 7 Nov 2026, with notes saying the permission is verbal). Each reciter is a `resources` row (source `way2quran`, group `chapter_recitations`, `source_key` = the Taybah reciter id, a small integer assigned once and never reused: 1 Muhammad Abadh, 2 Hossam El Din Ebadi) with one `recitations` row (`qirat` Hafs, `style` Murattal) and its `chapter_audio_files` rows.
   - **File ids** `2_000_000_000 + reciter_id * 1000 + surah`. MP3Quran uses `1_000_000_000 + moshaf_id * 1000 + surah`, QF uses its own record ids (below 30,000 today). The ranges cannot overlap while MP3Quran moshaf ids stay below 1,000,000. The id column is `unsignedBigInteger` (`2026_10_27_143839_create_chapter_audio_files_table.php`; spec §5). If any client holds it in an int32, `2e9 + n*1000 + 114` stays below 2,147,483,647 up to about 147,000 reciters.
   - **Key** `audio/way2quran/{reciter_id}/{surah:03}-{sha256[:16]}.mp3`. Headers as ADR 0061 decision 5.
   - **Manifest** `apps/api/resources/way2quran/manifest.json`, schema 1, `source: "way2quran"`, the same fields as the MP3Quran manifest. The `moshaf_id` field carries the reciter id (the importer reads the same shape). Per file, `source_url` is the exact URL fetched, `source_etag` is `null` (Way2Quran sends none) and `source_last_modified` records the HTTP `Last-Modified`. PHP ignores the extra field.
6. **Timings: the whole-surah aligner only.** Way2Quran publishes no timings. Every surah is aligned by `tools/recitation-align` (windowed alignment, then ayah starts snapped to pauses), written with `source: "aligner"`. The timing kind is `way2quran` (the enum value equals the `content_sources` code, because the importer resolves the source with it); the folder is `apps/api/resources/recitation-timings/way2quran/{reciter_id}/`. The timing import checks the audio `size_bytes` for every kind except `qf` (today only `mp3quran`, `TaybahTimingImporter.php:172`), so a set can never attach to other bytes.
7. **The source list is data.** `tools/mp3quran-ingest/mp3quran_ingest/way2quran_reciters.json` holds, per reciter: `reciter_id`, `slug`, `riwayah_folder` (`hafs-an-asim`), `name_ar`, `name_en`, `moshaf_name` (Arabic, ending « - مرتل» so the importer maps the style), `page_url`, and `files`: surah number to **exact file name**. No URL pattern is assumed. A lister command (`way2quran-ingest list`, plan step 6) reads the reciter page, keeps the Hafs URLs, HEADs each and writes the entry for the developer to review. Adding a reciter is: run the lister, review the JSON diff, dispatch the workflow. No code changes. The files list is also the `surah_list`: a reciter ships when every listed surah is ingested (ADR 0061, partial-recording rule), so Ebadi's 54 surahs ship as a complete set of what he lists, the other 60 shown unavailable (ADR 0062).
8. **Hidden until released, and the opposite default to MP3Quran's.** The import writes a Way2Quran reciter **inactive** unless its id is in `quran.way2quran_released_reciters` (empty at first). This is a different job from MP3Quran's `mp3quran_held_moshafs`, which also makes the CI plan refuse the moshaf. Here the CI must align and merge a reciter while it stays hidden, and Railway imports on merge, so a merged manifest alone would otherwise publish it. Releasing a reciter is one config line, made by the developer after the accuracy review.
9. **Copy path.** Way2Quran files are copied with `--via s3` only (the Worker is pinned to MP3Quran). The ingest refuses `--via worker` for this source. The workflow already uses `--via s3`. Locally, 1.8 GB goes over the developer's upload link; the workflow is the intended path. The Worker is unchanged.
10. **Resilience.** The source host timed out once on a HEAD. The ingest's `head_file` retries 5xx, timeouts and connection errors three times (waits 2, 4, 8 s) for every source; 404 is not retried. The download already resumes (`.part`) and checks the byte count against `Content-Length`.
11. **Accuracy gate before any reciter is shown.** No Way2Quran reciter has published or QF timings to compare against, so the gate is the A6(c) pause audit of `docs/plans/recitation-timings.md` (at least 90% of ayah starts at an audio pause, at least 83% steady, a surah with more than 10% of ayahs below the confidence floor is not shipped, ADR 0060 decision 8–9), on every surah of the reciter. One failing surah keeps the whole reciter hidden (ADR 0060: no surah-by-surah shipping). The numbers go into an addendum to ADR 0060. The A6(a) result against the trusted reference (Afasy) is also not recorded in ADR 0060 as far as the planner could find (no addendum exists on 7 Nov 2026), so these reciters are blocked on the same thing as Islam Sobhi (MP3Quran 253, held in `config/quran.php:119`; no written reason found).
12. **Cost.** About 1.85 GB (Abadh) plus 0.33 GB (Ebadi) is about 2.2 GB. At $0.015 per GB-month that is about $0.03 a month, and nothing while the bucket stays within the first 10 GB-month free (ADR 0061 decision 12; recheck pricing). The largest file seen is Abadh's surah 2 at 129,657,854 bytes, larger than any MP3Quran file in the manifest (moshaf 86 surah 2: 90,654,379). An offline download is per surah, as for every reciter.

## Consequences

- `CLAUDE.md` non-negotiable 2 must name Way2Quran's use of `audio.taybah-app.com` (developer edits).
- `Mp3QuranManifest`, `Mp3QuranImporter` and `Mp3QuranFileId` hard-code the source, key prefix, id base and config keys. They are generalised through a small source profile (plan step 1, a refactor proven by the existing tests passing unchanged), not copied.
- The classes keep their `Mp3Quran` names in this change. A rename is noise for a later change.
- The Sources screen is a static list (`apps/mobile/src/features/reader/screens/SourcesScreen.tsx`, array `SOURCES`) and MP3Quran is not in it yet, while `docs/plans/recitation-timings.md` line 58 says the screen reads `content_sources`. The two disagree; this ADR does not pick a side (plan question 3).
- Embedded cover art: the duration measure and the aligner's audio loading must use the audio stream only. A test builds a small generated file with a cover stream.
- The ingest tool keeps its folder and package name `mp3quran-ingest` (README states it now serves two sources).

## Open items for the developer

1. **Written confirmation.** Recommended, not required: a short written confirmation from each Sheikh, and from Way2Quran for the catalogue-wide scope, kept by the developer outside the repo and not quoted here. Not a blocker.
2. **Who owns the recordings: decided.** The tags name Midad (www.midad.com). Developer decision, 7 Nov 2026: the permission the developer holds covers these recordings; Midad is recorded here as the producer and credited (decision 2c). No further permission is sought before the upload.
3. **Decided 7 Nov 2026:** ids 1 (Abadh) and 2 (Ebadi), names as on Way2Quran, hidden until released (decision 8), `permission_status` `granted`, and Abadh ships first, Ebadi after as a data-only add. Sources credit: no frame, one Way2Quran entry on the existing screen (decision 2).
