# Phase 8 — data format, validator and review report

Exact file formats for ADR 0089. Examples use **placeholder quotes** (`FIXTURE quote …`) as the agent rules require; real quotes come from the book through `seerah:quote` and are never typed. Place names, coordinates and ids in the examples are illustrative; real values come from steps 7 and 8.

## Folder

```
apps/api/database/data/seerah/
  source/
    1345IbnCafifiKhudari.NurYaqin.<version>-ara1   pinned OpenITI file, byte for byte (SHA-256 in config/seerah.php)
    LICENSE-NOTICE.md                              licence, credit, changes made (as for hadith chapters, ADR 0076 §8)
  book/structure.json                              GENERATED by seerah:canonicalize, committed: every section (level, number, exact heading, page, paragraph range)
  gazetteer.json                                   all places, region -> city -> landmark
  events/
    E1.json  E2.json  E3.json  E4.json             one file per review batch (the batch names are in config seerah.batches)
  routes.json                                      journeys drawn on the map
  milestones.json                                  the six named markers, each tied to an event
  exclusions.json                                  sections that have no event, with a reason
  map/
    layout.region.json  layout.makkah.json  layout.madinah.json   drawn positions, label priority, route paths
  reviews/
    G.json  E1.json  E2.json  E3.json  E4.json  M.json           developer sign-offs (hash-bound), written only by seerah:approve
```

The canonical text itself is **not committed**. It is derived on every run by `seerah:canonicalize` from the pinned file (deterministic; its SHA-256 is also pinned in `config/seerah.php`, so a change to the transform that alters a byte fails).

Formatting: UTF-8, two-space indent, fixed key order, Arabic as literal characters (never `\u` escapes), one trailing newline. `seerah:fmt --check` (CI) rejects anything else, so every diff is one field per line. JSON has no comments, so every record has a free `note` field. The loader checks the key order and the layout of every file (V2), so a file that `seerah:fmt` would change fails.

## `gazetteer.json`

```json
{
  "format": 1,
  "source_sha256": "<canonical text sha256>",
  "places": [
    {
      "id": "makkah",
      "parent": "hijaz",
      "kind": "city",
      "name_ar": "مكة",
      "names_in_book": ["مكة", "أم القرى"],
      "name_en": null,
      "geo": {
        "lat": 21.3891,
        "lng": 39.8579,
        "precision": "city",
        "source": "wikidata:Q5806",
        "note": "illustrative value; real one set in step 8"
      },
      "evidence": [
        { "para": "p00123", "quote": "FIXTURE quote 1 — not from the book" }
      ],
      "origin": "drafted_by_agent",
      "flags": [],
      "note": null
    },
    {
      "id": "makkah.kaaba",
      "parent": "makkah",
      "kind": "landmark",
      "name_ar": "الكعبة",
      "names_in_book": ["الكعبة", "البيت"],
      "geo": { "lat": 21.4225, "lng": 39.8262, "precision": "exact", "source": "wikidata:Q35774", "note": null },
      "evidence": [
        { "para": "p00201", "quote": "FIXTURE quote 2 — not from the book" }
      ],
      "origin": "drafted_by_agent",
      "flags": [],
      "note": null
    }
  ]
}
```

- `kind`: `region` (الحجاز، الشام، الحبشة), `city` (مكة، المدينة، الطائف، بدر), `landmark` (الكعبة، غار حراء، شعب أبي طالب، دار الأرقم، جبل ثور). A landmark's parent is a city or a region; a city's parent is a region.
- `names_in_book`: the exact strings the book uses (with prefixes stripped only by search, not in storage). At least one must appear inside one `evidence` quote (validator V5).
- `geo.precision`: `exact` | `site` | `city` | `area`. `geo.source`: `wikidata:Q…` or `manual` (then `note` says how it was placed). OpenStreetMap is not used (ODbL ShareAlike); Wikidata coordinates are CC0.
- `name_en`: null until the developer answers Q19.
- `origin`: `drafted_by_agent` | `curated_by_developer`. Informational; **both** need sign-off.
- `flags`: `disputed_location`, `approximate_location`, `not_in_book_directly` (a region added for hierarchy only), each with a `note`. A flagged place needs a developer decision recorded in the sign-off.
- Where a place is drawn is **not here** (see `map/layout.*.json`).

## `events/<batch>.json`

```json
{
  "format": 1,
  "batch": "E1",
  "period": "Makkah before the Bi'tha",
  "events": [
    {
      "id": "e042",
      "section": "s042",
      "title_ar": "<the exact heading text of s042, copied by the tool>",
      "span": { "from": "p00310", "to": "p00338" },
      "kind": "event",
      "place": {
        "id": "makkah.kaaba",
        "basis": "stated",
        "evidence": [
          { "para": "p00312", "quote": "FIXTURE quote 3 — not from the book" }
        ],
        "also": []
      },
      "year": {
        "basis": "stated_age",
        "age_from": 35,
        "age_to": 35,
        "era": "bh",
        "hijri_from": 18,
        "hijri_to": 18,
        "certainty": "stated",
        "evidence": [
          { "para": "p00310", "quote": "FIXTURE quote 4 — not from the book" }
        ]
      },
      "route": null,
      "order_exception": null,
      "origin": "drafted_by_agent",
      "flags": [],
      "note": null
    }
  ]
}
```

Field rules:

| Field | Values and rule |
| --- | --- |
| `section` | A section id from `book/structure.json`. |
| `title_ar` | **Must equal** the section's heading text exactly. The tool fills it; V8 checks it. No event title is written by hand. |
| `span` | Paragraph range inside the section. Spans of one section **partition** its paragraphs: no gap, no overlap (V13). A section with a single event omits `span` and takes the whole section. |
| `kind` | `event` (shown on the map) or `background` (a heading inside the period with a date but no place worth a pin, shown on the timeline and the list only). Sections with neither are in `exclusions.json`. |
| `place.basis` | `stated` (a quote names the place, or a descendant of it) · `implied` (the book gives context, not the name) · `unstated`. |
| `place.also` | Other place ids named in the span, shown on the event page, not pinned. |
| `year.basis` | `stated_age` (the book gives the Prophet's age) · `stated_hijri` (the book gives a Hijri year or an ordinal year) · `stated_relative` («بعد كذا بسنة») · `section_year` (inherited from a year heading, V12) · `implied` · `unstated`. |
| `year.era` | `bh` (ق.هـ) or `ah` (هـ). Derived from `age_from` by the convention in Q6, checked by V11; `hijri_*` are the year numbers in that era. |
| `year.certainty` | `stated` (the quote gives it) · `approximate` (the quote says «نحو» or «قبل»; the range is wider) · `developer_assigned` (not stated; see below). |
| `flags` | `place_not_stated`, `year_not_stated`, `disputed_date`, `disputed_location`, `order_exception`, `evidence_outside_span`. Each carries `note`. |
| `order_exception` | `null`, or `{ "note": … }` when the book tells an event out of time order (V12). |

**Anything the book does not state explicitly** (`basis` is `implied` or `unstated`, or `certainty` is `developer_assigned`) must carry the matching flag and **cannot be signed off by an agent's edit**. The developer writes the decision in the sign-off file's `decisions` map (`"e042": { "year": { … }, "note": … }`); the validator applies it as an override and the report shows it in a distinct colour. If the developer declines to assign, the event is `background` with no year on the map or is excluded; it is never given a guessed year.

### The «أخرى» place and the «غير محدد» year bucket (developer, 14 Nov 2026)

- Place `other` is a fixed gazetteer entry: `{ "id": "other", "parent": null, "kind": "region", "name_ar": "أخرى", "geo": null, "evidence": [], "flags": ["not_in_book_directly"] }`. It needs no coordinates and no evidence; V4, V5 and V6 exempt it. An event that uses it has `place.basis: "unstated"`, `place.id: "other"`, empty evidence and the flag `place_not_stated`.
- Year bucket: `year.basis: "unspecified"`, `age_from`, `age_to`, `hijri_from`, `hijri_to` all `null`, `era: null`, `certainty: "unspecified"`, flag `year_not_stated`. Shown after age 63 on the timeline as «غير محدد» and in its own group in the list.
- Nothing is placed in these buckets by guessing: the validator allows them only with the flag, and the report lists every such event **first** (view 0b), before the periods.
- Use them only when the book's span gives no stated place or year. If a quote states it, the event gets the real place or year.

## `routes.json`

```json
{
  "format": 1,
  "routes": [
    {
      "id": "r-hijra",
      "name_ar": "<exact words from a heading or the evidence quote>",
      "stops": ["makkah", "makkah.thawr", "madinah"],
      "events": ["e105", "e106"],
      "evidence": [ { "para": "p01200", "quote": "FIXTURE quote 5 — not from the book" } ],
      "kind": "hijra"
    }
  ]
}
```

`kind`: `trip` (الشام), `hijra`, `taif`, `ghazwa`, `habasha`. The curve drawn between stops is in the layout file (V14 checks its end points sit on the stops' drawn positions).

## `milestones.json`

Six entries (المولد، البعثة، الهجرة، بدر، الفتح، الوفاة). Each is `{ "id": "birth", "label_ar": …, "event": "e001" }`. Its age and year are **read from that event**, never typed here and never taken from this plan: the book's statement decides (open item: the book's stated age at death must be confirmed against the 0 to 63 axis, Q6).

## `exclusions.json`

```json
{ "format": 1,
  "excluded": [
    { "section": "s001", "reason": "front_matter", "note": null },
    { "section": "s210", "reason": "no_chronology", "note": "the book's closing section; not an event" }
  ] }
```

`reason`: `front_matter` · `genealogy` · `no_chronology` (descriptions, characteristics) · `prophecy_background` · `other` (note required). The report lists every exclusion; the developer signs `exclusions` in batch `G`.

## `map/layout.<level>.json`

```json
{
  "format": 1,
  "level": "makkah",
  "parent_place": "makkah",
  "viewbox": [0, 0, 1000, 1000],
  "art": "design-assets/seerah/map-makkah.svg",
  "positions": [
    { "place": "makkah.kaaba", "x": 512, "y": 498, "label_priority": 100, "label_side": "end" }
  ],
  "route_paths": [
    { "route": "r-hijra", "segment": ["makkah", "makkah.thawr"], "d": "M …" }
  ]
}
```

`label_priority` (0–100) decides which label survives a collision; ties break by event count then book order. Layouts are reviewed **visually** (the report draws them, and the frames approve the art), not by reading numbers.

## `reviews/<batch>.json` (developer only)

```json
{
  "format": 1,
  "batch": "E1",
  "signed_by": "developer",
  "signed_at": "2026-12-01",
  "records": { "e001": "<sha256 of the record>", "e002": "<…>" },
  "decisions": {},
  "digest": "<sha256 of the sorted id:hash lines>"
}
```

Written by `php artisan seerah:approve E1`, which the developer runs after reading the report; the command prints the digest, and the report's footer shows the same digest so the developer can see that what he approved is what the file says. **No agent runs `seerah:approve` and no agent writes `reviews/`** (rule in every step brief). The record hash is the SHA-256 of the record's canonical JSON (fixed key order). Status is derived: `approved` (listed, hash equal), `stale` (listed, hash differs), `draft` (not listed).

## Validator (`php artisan seerah:validate [--release]`)

Pest runs it on committed data and on placeholder fixtures; CI runs it on every change under `apps/api/database/data/seerah/**`, `apps/api/app/Domains/Seerah/**` and `config/seerah.php`. Three modes after the 14 Nov revision: **`--structure`** (CI and the overnight run: V1 to V15, V18, V19; `draft` records are allowed; `other` and the year bucket are allowed with their flag), **dev** (same, plus warnings), **`--release`** (needs sign-offs). **Dev mode** reports errors and warnings; **`--release`** also fails on any `draft` or `stale` record, any flag without a decision, any uncovered section. The importer refuses to run in production without `--release` passing.

| # | Rule | Severity |
| --- | --- | --- |
| V1 | The source file SHA-256 equals the pin; the canonical text SHA-256 equals its pin. | error |
| V2 | Every file parses, matches `seerah:fmt`, has `format`, no unknown key, unique ids, ids match their pattern. | error |
| V3 | Every evidence quote is a byte-exact substring of the stated paragraph of the canonical text; non-empty; no leading or trailing whitespace; at least 8 characters. | error |
| V4 | Every place id referenced anywhere exists; the tree has no cycle; kinds nest `region > city > landmark`. | error |
| V5 | Every place has at least one evidence quote containing `name_ar` or one of `names_in_book` (a `not_in_book_directly` region is exempt and flagged). | error |
| V6 | Coordinates present and inside a plausible box; a landmark is within 40 km of its parent city, a city inside its region's box; `geo.source` set. | error / warning |
| V7 | Every place used by an approved event has a drawn position at its display level, inside the viewbox; a drawn pair keeps its compass order (north/south, east/west) from the coordinates, with a margin. | error / warning |
| V8 | An event's `section` exists, `title_ar` equals the heading exactly, the span lies inside the section. | error |
| V9 | An event has a place and a year. `basis: stated` needs at least one evidence quote, **inside the event's span** (else the `evidence_outside_span` flag), and the quote contains the name of the place or of one of its descendants. | error |
| V10 | `implied`, `unstated` and `developer_assigned` carry their flag and cannot count as approved without an entry in the sign-off `decisions` map. | error |
| V11 | `age_from <= age_to`, both in 0..63; `era` and `hijri_*` agree with the age by the convention (Q6); for `stated_age` the quote contains a digit or an age word; for `stated_hijri` an ordinal or digit (heuristic, warning). | error / warning |
| V12 | Events in book order have non-decreasing `age_from`, except `order_exception`. A section under a year heading («السنة الثالثة» and so on) must not hold an event of another year. | error |
| V13 | Every section is covered by events whose spans partition it, or is in `exclusions.json`. Nothing is covered twice. | error |
| V14 | A route's stops exist and have drawn positions; its events exist; the drawn path starts and ends on the stops; the route's years lie within its events' years. | error |
| V15 | The six milestones exist, point at events, and are in age order. | error |
| V16 | Every `{…}` run in the canonical text (the book's way of quoting an ayah) is classified against the bundled Tanzil text, normalised: `matched` (surah:ayah recorded in a generated index, for the later link feature) or `unmatched` (listed for the developer). No Quran text is stored outside the book's own paragraphs. `packages/quran-text-check` is untouched. | error for a column or file that holds Quran text; list for the rest |
| V17 | Review state: each record is `approved`, `stale` or `draft` as above; dev mode lists them, `--release` requires all `approved`. | error in release |
| V18 | Every record has `origin`; no record has an unknown value. | error |
| V19 | Counts: sections, events, places, exclusions, per batch, printed; the release pin of those counts goes in `config/seerah.php` and CI fails when the committed data changes them without a bump. | error |

## Review report (`php artisan seerah:report`)

One self-contained, right-to-left HTML file (inline CSS and a small inline script, no network, no framework) written to `apps/api/storage/app/seerah/report/index.html`, plus `summary.md`. CI uploads it as an artefact. It is **not committed** (it would churn). It is a review artefact, not a design, so ADR 0087 does not apply to it. It never edits data.

| View | Content |
| --- | --- |
| **0b. «أخرى» and «غير محدد» first** | Every event in the place `other` or the year bucket `unspecified`, with the book's span around it, grouped by section, so the developer can assign the real place or year (or confirm the bucket). Shown above everything else after the overview. |
| **0. Overview** | Counts per batch (events, places, sections, exclusions), status counts (approved, stale, draft), open flags, validator errors and warnings, the pins (source commit, SHA-256s). |
| **1. By period → year → event** | Batch (E1..E4) → age and era («ق.هـ ١٣» style label) → event: the book's heading, status chip, place name and its path (region › city › landmark), certainty, `basis`, **the year quote and the place quote shown in their paragraph with the quote highlighted**, the page number, and a button to jump to the place. Flags in red. |
| **2. By place → events** | The gazetteer tree. Each place: names in the book, evidence quote in context, coordinates and source, drawn position, status, and all events that use it (year order). Landmarks with no event are listed as «بلا حدث». |
| **3. Map check** | The three SVG maps with every place drawn at its position, labelled, colour by status; a year slider that dims events outside the year (the same logic the app uses, so the developer sees the highlight behaviour before any app code exists). |
| **4. Flags worklist** | Every record that needs a developer decision (place or year not stated, disputed, approximate, order exception, evidence outside span), with the book's surrounding paragraphs and a place for the decision to be noted (the decision is then recorded by the developer in the sign-off file). |
| **5. Coverage** | Every section in book order: the events that cover it, or its exclusion and reason; paragraph partition check. |
| **6. Quran runs** | Every `{…}` run, matched or not, with the surah:ayah when matched. |
| **7. Batch sign-off block** | For the chosen batch: the record count, the digest, and the exact command to run. |

The report's filters: batch, status, flag, certainty, place subtree, age range. Print stylesheet included so a batch can be saved as a PDF to read on paper.

## Authoring tools (deterministic helpers; no text is generated)

| Command | Does |
| --- | --- |
| `seerah:find <term> [--section=s042]` | Searches the canonical text with the hadith/Quran-style normaliser; prints paragraph ids, page, and the match in context. |
| `seerah:quote <para> --words=4-19` | Prints the exact substring and the JSON snippet `{ "para": …, "quote": … }`. The only way quotes enter the data. |
| `seerah:place-candidates` | Lists frequent words after place cues (إلى، من، في، مدينة، جبل، غار، وادي، بئر، غزوة، سرية، سوق) with counts and contexts, as a **worklist**, never as a gazetteer. Entries are accepted or rejected by the curator. |
| `seerah:skeleton <batch>` | Writes an event skeleton for a batch: id, section, `title_ar` (heading copied), span, empty place and year (so no title is ever typed). |
| `seerah:fmt [--check]` | Canonical JSON formatting. |
| `seerah:approve <batch>` | Developer only. Writes `reviews/<batch>.json`. |

## Build decisions for steps 4 to 6 (14 Nov 2026)

These are the decisions the build made where the first version of this file did not fit the book. They are in the code and tested; the list is here so the next reader does not have to find them.

- **Edition facts.** `book/structure.json` has 258 sections: `s001`, `s002` are `front`, the other 256 are `heading`. There are no `bab`/`fasl` levels, so the `number` and `parent` fields are gone. 14 sections have no paragraph (`paragraph_from` and `paragraph_to` are null). No `{…}` braces: quoted Quran is plain text in the paragraphs, so V16 only lists braced runs, and there are none.
- **Year headings.** The eleven headings «السنة الأولى» … «السنة الحادية عشرة» (config `seerah.year_headings`, Hijri years 1 to 11) are sections of their own. A section belongs to the last year heading at or before it (`BookIndex::yearOf`). The Hijri year of an age follows `AgeConvention` (age 53 is `ah` 1, age 52 is `bh` 1). The heading «السنة السادسة» is `s117`; the year headings `s060` to `s225` carry no text of their own except `s090`.
- **Exclusion reason `year_heading`** is added: a year heading with no text is excluded with this reason (or carries an event).
- **Batches** (config `seerah.batches`, section ids inclusive, start titles checked by V13): **E1** `s003`–`s019` (17 sections, «النسب الشريف» to «حركة الأفكار قبل البعثة»); **E2** `s020`–`s044` (25 sections, «بدء الوحي» to «العقبة الثانية»); **E3** `s045`–`s116` (72 sections, «هجرة المسلمين إلى المدينة» to «فرض الحج»); **E4** `s117`–`s258` (142 sections, «السنة السادسة» to the end). The front sections `s001` and `s002` belong to no batch; they are excluded as `front_matter` when the data is signed.
- **Flags are objects** `{ "code", "note" }`. The codes are a closed list (`FlagCode`): `place_not_stated`, `place_implied`, `year_not_stated`, `year_implied`, `year_developer_assigned`, `disputed_date`, `disputed_location`, `approximate_location`, `order_exception`, `evidence_outside_span`, `not_in_book_directly`. A place carries only `not_in_book_directly`, `disputed_location` or `approximate_location`; an event carries the others (V18).
- **A region may carry `geo.box`** `[south, west, north, east]`, and a city is checked against its region's box (V6). A region with no coordinates is allowed only when flagged `not_in_book_directly` (the root region).
- **Decisions are not overrides.** A sign-off's `decisions` map holds `{ "codes": [...], "note": "..." }` for a flagged record. The developer writes the assignment into the record itself, so the record's hash covers it. Overrides in the decision are not implemented. Release (V10) needs a decision whose codes cover every flag of the record.
- **Hashes.** A record's hash is the SHA-256 of its compact JSON in the file's key order (`RecordSerializer`). A sign-off's digest is the SHA-256 of its sorted `id:hash` lines (`ReviewRecords::digest`). The report prints the same digests that `seerah:approve` writes.
- **Milestones** use the key `id` (`{ "id": "birth", "label_ar": …, "event": … }`); the six configured keys are `birth`, `bitha`, `hijra`, `badr`, `fath`, `death`.
- **Validation modes.** `seerah:validate` (default `--structure`, what CI runs): errors fail, drafts are allowed, and an uncovered section or a missing milestone is a **warning**. `--complete` makes uncovered sections, paragraphs no event covers, missing milestones and (with a pin) counts **errors**; this is the flag to use as the data lands, before the release run. `--release` implies `--complete` and needs every record approved, every flag decided and every group signed. Counts (V19) are checked against `seerah.counts` on the committed data only, not over `--source`.
- **Rules that did not change in meaning**: V3, V8, V9, V11, V12, V13 (partition) and V17 are as written; V13 keeps «nothing covered twice» as an error in every mode.
- **Authoring tools.** `seerah:quote <para> <from-word> <to-word>` takes two words, not word numbers; the words match after the search normalisation and punctuation is ignored. `seerah:find` uses the same normalisation as `HadithSearchTextNormalizer` (a test checks they agree) and reports byte offsets. `seerah:skeleton <batch>` writes `e` plus the section's number as the event id, copies the heading, sets the span from the structure and leaves place and year null; it refuses a file that already holds events. `seerah:place-candidates` shows the book's own spelling.
- **Report.** `seerah:report` writes `storage/app/seerah-report/index.html` (ignored by git through `storage/app`). Views: overview (0), «أخرى» and «غير محدد» (0b), by batch, age and event (1), by place (2), map check (3, positions and a year slider), decisions (4), coverage with exclusions, routes and milestones (5), Quran runs (6), sign-off digests and commands (7). It writes nothing into the data folder.
- **Approval.** `seerah:approve <group>` refuses in production, in CI (`CI` or `GITHUB_ACTIONS` set), in a non-interactive run, when the validator reports errors, when the group is empty, and when a flagged record has no decision in the existing file. It asks for the group's name before it writes.
